# FootMate 통합 디자인 기준 (웹 보고서 + 발표자료)

## 적용 범위
- 웹: 메인 9개 섹션, 월간 손익 계산 페이지, 의사결정 메모, 발표자료 뷰어
- 발표자료: 사업성 분석 PPTX 9장 + 중장기 경영전략 PPTX 6장
- 변경 원칙: 사업 가정·수치·손익 계산식·표의 산식·결론·출처를 시각 고도화 작업에서 변경하지 않는다.

## 웹 UI·UX
- 9개 섹션을 유지하고 목차/해시/뒤로가기/키보드 포커스를 보존한다.
- 스크롤 진행 표시를 제공하되 스크린리더 반복 안내를 만들지 않는다.
- 모바일 320px 이상, 200% 확대 시 콘텐츠가 잘리거나 수평 스크롤이 발생하지 않아야 한다.
- 핵심 카드·시나리오·손익 표는 색상과 글자 크기만으로 구별하지 않는다.
- 데이터와 인터랙티브 시뮬레이션은 기존 계산 및 입력값 검증 로직을 유지한다.

## PPT
- 사업성 분석 9장: 01 대표 판단, 02 책임, 03 전환, 04 단위 손익, 05 차이, 06 통제, 07 자원, 08 ROI, 09 투자 결론.
- 전략 6장: 01 표지, 02 공급 성장, 03 협상 효과, 04 월 경제적 손익, 05 자원관리, 06 결론.
- PPTX는 수정 가능한 원본을 유지한다. 웹에 쓰이는 PNG/JPG는 **PPTX 렌더 결과에서 재생성**한다.
- 발표 시 1장에 하나의 주요 결론을 우선 노출한다. 이미 명확한 차트는 무리하게 다른 종류로 바꾸지 않는다.
- **월 경제적 손익(기회비용 포함)**과 **연간 투자 후 현금수지(기회비용 별도)**를 동일 지표처럼 표시하지 않는다.
- 원본 15장의 텍스트 값과 개수, 핵심 시나리오 수치는 원본 그대로 보존한다.

## 검증 명령
- `python qa/unify-web-and-presentations-20261111.py`: PPTX 수정 + 15개 미리보기 재생성(렌더 도구 필요)
- `python qa/crosscheck-case-study-presentations.py`: 웹 본문·PPT 2종 숫자와 핵심 문구 대조
- `npm run test:report`: 모바일·데스크톱·200% 확대·접근성·발표자료 동작 테스트
- 자동화: GitHub Actions `FootMate Design Sync` 및 `FootMate Case Study QA`

> UI 수정을 위한 문서이며 실제 영업/재무 실적 인증을 의미하지 않는다.

## 2026-11-16 P0–P2 보완 발표자료(별도 6장) · 배포 전 원칙

- 기존 웹 보고서 **9개 섹션**, 본편 PPTX **9장**, 중장기 PPTX **6장** 및 이들의 이미지 미리보기 15개와 숫자·표·계산식은 원본 그대로 보존한다.
- 별도 보완 발표자료 **6장**(`src/case-study/strategy-brief.html`, `downloads/footmate_strategy_p0_p2.pptx`)은 기존 15장을 대체하지 않는다. 양쪽은 같은 `strategy-brief-data.js` 문구를 사용하며, 편집용 PPTX와 웹 텍스트의 일치 여부를 QA로 대조한다.
- 본문에 추가하는 P0–P2 요약은 02 시장·경쟁, 03 사업모델, 08 실행계획 영역 안에 배치하되 목차/해시/기존 31개 표/고유 H1/기존 계산기를 변경하지 않는다.
- **자료 배치:** 본문 01의 `발표자료` 영역에 사업성 검토 9장·5개년 성장 전략 6장·사업 전략 6장을 같은 카드 형식(제목, 장수, 발표 보기, PPTX 받기)으로 배치한다. 02·03·08장의 분석 내용은 유지하고, 08장 하단에 별도의 중복 발표자료 버튼을 추가하지 않는다. 320px부터 2D 넘침 없이 1열, 넓은 화면에서 3열 표시한다.
- 배포 기준: 기존 회귀·발표자료 수치 대조 + 새 6장 편집 도형·문구 검사 + 320/390/1440px 접근성·넘침 검사. 새 PPTX는 별도로 실제 렌더/편집 확인이 필요하며 자동 검사만으로 화면 품질을 인증하지 않는다.
- 신규 PPTX의 PNG/JPG를 웹 자산으로 추가할 경우 반드시 **PPTX에서 렌더하여** 생성한다. 이번에는 신규 PPTX 이미지 미리보기를 게시하지 않으며 HTML 텍스트 발표로 구별한다.
- 검토 및 배포 게이트: [배포 전 점검 절차](PREDEPLOY-STRATEGY-ADDENDUM-20261116.md)를 참조한다. 운영 배포 완료와 GitHub PR 병합은 서로 다른 상태다.


## 2026-11-17 본문 밀도·근거 연결 기준

- **섹션별 역할:** 01 결론·발표자료, 02~03 시장/제휴 근거, 04 공급 가정, 05 손익 계산, 06~07 시스템/통제, 08 8주 실증·중장기 계획, 09 조건부 투자 판단을 유지한다. 섹션을 늘리거나 기존 표를 이동하지 않는다.
- **05 손익·08 실행:** 핵심 손익 계산·로드맵·주요 차트는 노출하고, 기존 상세 산정표는 접기/펼치기로 유지한다. 펼침 제목만 간결하게 조정하며 원래의 7개·12개 표, 수치, 산식, 해시 이동 경로를 보존한다. 8주 실증 목표와 5개년 전망 가정은 구분한다.
- **09 결론:** 실증 착수·검증 지표·중단 조건을 세 카드에 배치하고 각 카드의 설명은 40자 이내로 유지한다. 실제 승인·집행이 없음을 구분하며 새 정량 목표를 발명하지 않는다.
- **근거 링크:** 02는 기존 기관·경쟁 서비스의 공식 출처를 유지하고, 03에는 타사의 제휴 운영 공개 안내를 참고 링크로 둔다. `docs/`는 Workers 정적 자산에서 제외하므로 본문에 내부 GitHub 문서 링크를 추가하지 않는다. 상세 검토 문서는 README에서 제공한다.
- **교차검증:** 9개 섹션·31개 표·PPTX 9+6+6장·XLSX·계산식과 기존 발표자료 이미지는 변경하지 않는다. 320/390/1440px·200% 확대·키보드·접근성 및 원문/표 수량 QA를 유지한다.
