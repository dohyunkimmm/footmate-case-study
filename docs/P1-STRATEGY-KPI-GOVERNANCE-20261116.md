## 2. 보고 규칙과 데이터 계보

1. **기준 시점/분모 고정:** 동일한 시간대·지역·경기·예약 ID 기준으로 공급→충원→경유→취소→완료 퍼널을 재현한다. 합성/테스트·취소·노쇼·실제 운영을 분리.
2. **금액 일치:** 거래액(GMV)과 플랫폼 수수료 매출을 구분한다. 완료건 지원·유입·IT 비용을 공헌이익에서 한 번 차감했다면 원장 연결 시 중복 차감하지 않는다.
3. **관측 수준 표시:** `실측` / `합성 데이터` / `사업 가정` / `목표` / `미수집`의 다섯 상태를 모든 지표에 붙인다. 미수집은 '0'이나 실패로 표현하지 않는다.
4. **실적-계획 차이 분해:** 공급처/슬롯 수 → 충원율 → 경유율 → 취소/완료율 → 단위수수료·결제/CS·CAC → 고정비 순으로 수량·단가·비용 영향 분리. 2개 요인의 교차효과는 별도 기록.
5. **반복 수요의 관측 기간:** 완료 후 30일을 채우지 않은 신규 고객은 재참가율의 분자와 분모 모두 제외한다. 30일 이전 데이터만으로 재참가 성공/실패 판단 금지.
6. **정정 이력:** 데이터 원장 버전, 집계 SQL/스프레드시트 버전, 정정 사유, 검토자·승인일·변경 전/후 금액을 기록한다. 집계 기준이 바뀌면 과거 비교치도 재산정하거나 단절을 명시한다.
7. **월마감:** 원본 제안의 월말 **+3일 원장 대사**, **+5일 원인 보고**를 채택한다. 경영진 승인·정기회의는 제안 수준이며 실제 진행 사실 아님.

## 5. 보고 흐름·품질 확인

**주간 보고:** 공급·안전 게이트 → 완료 퍼널 → 주요 이슈/에스컬레이션 → 예산·약정 → 다음 주 실험/결정.

**월간 경영진 보고(안):** Executive Summary → 전략과제별 KPI → 계획/실적/전망 구분 → 손익/현금 차이 요인 분해 → 예산·리스크 → 승인·보류·철회 결정.

**QA 성격 구분:** GitHub Actions의 브라우저·문서 회귀 통과는 사이트/산출물 검사를 뜻하며, 시장 수요·가설 타당성·실제 사업운영 성공을 입증하지 않는다. 이 KPI 체계는 실행·측정이 이루어진 후에야 운영 성과로 평가 가능하다.
